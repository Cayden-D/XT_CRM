# 销途 AI CRM

面向 1688 店铺的 AI 经营系统：商品采集与上架、客服绩效、线上客户经营。早期产品范围见 [PRD.md](./PRD.md)。

## 已实现

- 经营看板（默认首页）：成交、退款、接待、转化、首次响应及趋势，待处理事项直达，客服表现、客户结构与商品上架进度
- 客户经营：1688 线上客户档案、分层筛选、跟进与复购、附件、导出
- 客户（线下客户）：国内省市区地址、统一社会信用代码、联系人和客户 360，可与线上客户关联
- 产品目录：默认展示店铺在 1688 上架的商品（来自“同步平台商品”，含价格区间、库存、SKU 数和按已同步订单统计的近 30 天销量，可按在售/已过期、店铺、关键词/货号筛选和排序，点开可刷新、关联正式产品、改库存）；“产品资料”页签保留内部产品规格与阶梯价，用于生成上架草稿
- 客服绩效：1688 绩效应用授权、客服对比、聊天分析、订单归属（9 种方案）、KPI 排行与工资
- 图片工作台：采集商品详情展示主图与详情图并检测他人水印/品牌 Logo；「图片编辑」做白底图、换背景（千问）和改尺寸；「电商套图」用 GPT-Image-2.5 生成白底、场景、细节、模特、卖点、规格 6 张主图；可开启 Agent 为被标记的主图自动生成替代图（不修改、不去除原图水印）
- JWT 登录、租户隔离、RBAC、审计日志和 PostgreSQL 迁移
- 1688 店铺连接、加密令牌、平台商品同步、采集审核转正式产品、发布草稿和库存确认工作台（真实平台写入尚待验收）

全局 AI 助手已接入阿里云百炼千问。2026-10-14 起下线了线索、商机、报价、销售作战台（演示数据）和订单履约占位页：真实租户中没有任何线索、商机或报价记录，1688 询盘与成交已由「客户经营」「客服绩效」覆盖。对应数据表保留未删除，代码备份在 `backups/2026-10-14-legacy-crm-modules.tar.gz`。

1688 接入范围、配置、测试命令及尚未开放的接口见 [1688 接入设计与验收](./docs/1688-integration-design.md#8-首批实现与验收2026-09-29)。

## 1688 商品采集

1. 登录 CRM，进入“1688 商品采集 → 配置采集器”。
2. 安装 Tampermonkey 脚本，生成并复制专用采集密钥。
3. 在 1688 商品详情页点击右下角商品采集器，填写 CRM API 地址与密钥。
4. 点击“采集此商品”即可保存完整商品；在列表页可启动本页或多页批量采集。

采集结果会按来源商品 ID 幂等更新，完整保留标题、主图、详情图、视频、卖家、源类目、商品属性、价格区间、SKU 维度、规格价格、库存和原始商品快照，作为后续 AI 清洗与官方接口发布的输入。重新生成采集密钥会立即吊销旧密钥。

采集器 2.1.2 优先读取 `window.context.result.data.Root.fields.dataJson.tempModel.postCategoryId`，并与 `offerBaseInfo.catId` 核对后作为来源商品的发布子类目 ID；`topCategoryId` 只是顶级类目，不用于自动上品。明确 ID 缺失或冲突时仍会拦截自动发布；其它类目字段和面包屑链接仅作兜底。请在 Tampermonkey 更新本项目的 `scripts/1688-product-collector.user.js` 后重新采集缺类目的商品。若旧任务因类目缺失而被拦截，重新采集补齐 ID 后会自动重新入队（已生成正式产品或发布结果未知的任务不会自动重试）。本地提取回归：`npm run test:1688-collector-category`。

## 千问大模型

服务端通过阿里云百炼 OpenAI 兼容接口调用千问。将配置写入 `.env.local` 后重启 API：

```env
DASHSCOPE_API_KEY=YOUR_DASHSCOPE_API_KEY
DASHSCOPE_BASE_URL=https://YOUR_WORKSPACE_ID.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
QWEN_DEFAULT_MODEL=qwen3.8-flash
QWEN_TIMEOUT_MS=60000
```

右侧「销途 AI」助手会按问题调用只读工具查询系统数据（经营概览、客户列表与资料、客服绩效、商品销量、回复质量与站外交易风险、关键词命中；有绩效管理权限时，客户资料还带客服最近发给该客户的话，已遮盖联系方式），只读本地已同步数据，不消耗 1688 调用额度；工具按当前用户权限提供。提问时会附带当前页面、店铺和正在查看的客户（客户资料弹窗内可直接“问 AI”）。AI 不直接改数据：要求它写跟进、加/移除标签（可批量、可新建标签）或改所属客服（指定客服或恢复自动分配）时会生成确认卡片，点击“确认执行”后才保存（仅提问人、24 小时内、一次，执行时再校验 `customer_ops:update`）。侧栏右上角“历史对话”可恢复或删除以前的对话。验证：`npm run test:ai-assistant`（模拟千问，无需管理员密码）。一次含多次查询的回答通常需要 20–60 秒。

将地址中的 `YOUR_WORKSPACE_ID` 替换为真实北京业务空间 ID；API Key 必须具有该空间及目标模型的访问权限。允许使用 `qwen3.8-flash`、`qwen3.7-flash`、`qwen3.7-plus` 和 `qwen3.6-plus`，默认选择 `qwen3.8-flash`。API Key 仅由后端读取，不会发送到浏览器。现有旧地域地址仍可用于其获批模型，不保证可访问新版模型。

「系统设置 → Agent 上品 → 公共发布模板」可配置计量单位、库存扣减设置、供货方式、网上订购、报价方式及公共件重尺，当前企业的全部店铺共用。先应用数据库迁移 `020_1688_publish_template.sql`。初始不预选交易条款；保存后新草稿自动补齐，已有草稿可点击“应用公共模板（仅补空值）”，或重新运行 Agent。已填值保留，平台未开放或禁用的选项不会强行套用。按规格报价仍需 SKU 单价和库存。件重尺模板按商品配置含包装重量（正整数 g）、可选长宽高（cm，最多一位小数，长 ≥ 宽 ≥ 高），体积自动计算。商品草稿可手动修改覆盖；已有任一件重尺数值或按 SKU 数据时保留整组，不与模板混合补齐。清空件重尺模板只影响后续带入，不删除商品已填值。模板保存需要集成管理及发布权限，并通过版本号避免覆盖他人修改。`npm run test:1688-template` 验证配置和草稿应用；清空模板不会删除草稿已有值。

「系统设置」提供每店铺的 Agent 上品模式，默认关闭。确认图片/商品使用权、资料发送至百炼及自动发布授权后，新建发布草稿将自动生成标题、填写有依据的枚举属性、映射正式 SKU、筛查发布图片并校验规则，然后提交店铺；已有草稿可手动启动 Agent。图片检查仅对置信度至少 0.98、可读出具体公司/店铺名的水印或可准确指名的知名品牌 Logo 阻断；整图不可读、缺少必要资料或版本冲突也会中止。普通营销文字、车型轮廓和模糊标识不作为图片阻断理由。未知价格库存不猜填。AI 检查不能证明图片授权或给出法律侵权结论。

发布草稿中的「AI 图片工作台」可使用 `qwen-image-3.0`、`qwen-image-3.0-pro` 或 `qwen-image-2.1-pro` 文生图/图生图。图生图只接受草稿中已审核且通过同一图片检查的主图；生成图再次检测，明确公司水印、知名品牌 Logo 或整图不可读时禁止应用。新生成的 PNG 经校验后以私有对象持久化到阿里云 OSS；界面通过一小时有效的 V4 签名链接预览，过期后重新打开工作台可获取新链接。旧版尚未持久化的预览仍受原百炼链接的有效期限制。人工确认后填写店铺相册 ID，可将生成图上传至相册并替换/追加到本地草稿主图；此动作不会自动发布商品，也不会移除水印或替代授权核验。生成、OSS 存储和相册上传可能产生费用。若相册上传结果不确定，先核对相册，勿直接重试。模拟 OSS/网关和真实数据库验证命令：`npm run test:1688-images`；真实 OSS 上传与店铺相册写入尚待验收。

启用图片生成前，在 `.env.local` 配置 `OSS_REGION=oss-cn-beijing`（按实际 Bucket 地域填写）、`OSS_BUCKET`、`OSS_ACCESS_KEY_ID` 和 `OSS_ACCESS_KEY_SECRET`，然后重启 API。请使用私有 Bucket、最小权限 RAM 凭据，并限制其对 `1688-agent-images/` 前缀的读写权限；不要在浏览器或聊天中传递密钥。未配置 OSS 时，图片工作台会在计费的模型调用前返回配置错误。

可选设置 `OSS_CUSTOM_DOMAIN=https://img.example.com` 作为私有图片预览域名。先在 OSS 将该精确域名绑定至同一个 Bucket，配置指向 Bucket 外网域名的 CNAME 和有效 HTTPS 证书，再重启 API。此设置只改变一小时有效的 V4 签名预览链接；服务端上传、读取和删除仍使用 OSS 原生 endpoint。未设置时预览继续使用 Bucket 原生域名。不要把已有签名链接的域名直接替换成自定义域名，因为 V4 签名包含请求 Host。

已有发布草稿的 Agent 流程从已审核产品及明确类目开始；采集队列另有独立开关和来源资料闸门，不会回溯批量处理历史商品。任务结果入库，发布结果未知不自动重试。API/模型/店铺首次真实写入验收需另行验证。`npm run test:1688-agent` 使用模拟模型与网关验证自动提交及中止保护，不写真实店铺。模型配置调整后重启 API，在系统设置使用「测试模型连接」验证权限。

「采集 Agent 队列」是独立的自动化开关，默认关闭。先开启目标店铺的 Agent 上品模式，再在左侧「上架队列」的「自动上架设置」中确认开启该店铺的“采集后自动上品”；每个租户一次只能选一个目标店铺。仅开启后的新采集 1688 商品自动入队，旧采集记录可在详情中手动入队。后台按 `AGENT_QUEUE_CONCURRENCY`（默认 2）有限并发处理，`AGENT_QUEUE_POLL_MS`（默认 3000 毫秒）轮询；关闭队列或 Agent 模式会取消尚未开始的任务，并在平台提交前阻止正在处理的任务。队列先核实原类目 ID、人民币 SKU 价格和整数库存，再用千问检查主图、全部详情图及 SKU 图；仅明确的公司/店铺水印、知名品牌 Logo、整图不可读或资料不齐会在队列表显示原因，不会自动移除标识或尝试发布。安全图片保持原来源，详情图整理成发布详情，标题由现有 Agent 生成；来源类目与平台规则一致时，按名称精确映射采集属性，直接预填文本输入，并只在枚举值唯一匹配时预填选项；占位文字、歧义和缺失值不猜填。已有草稿再次运行 Agent 时也会补入尚未填写的来源属性，不覆盖人工值。规则校验通过后提交平台，平台可能继续审核，不能把“已提交”视为最终上架。提交结果未知或进程在提交阶段中断时不会自动重试，须人工核对。数据库/模拟模型与网关验证：`npm run test:1688-queue`；真实店铺写入尚未验收。

「上架队列」独立显示任务列表，支持按商品标题、任务状态及目标店铺筛选，并按每页 10 / 20 / 50 条进行服务端分页。商品标题、店铺名称和处理结果最多展示两行，点击商品标题或「详情」查看完整内容；手机端使用卡片布局。自动上架开关集中在页面顶部可展开的「自动上架设置」中。

自动图片检测接受 HTTPS 的 `cbu数字.alicdn.com` 图片，以及 `img.alicdn.com/imgextra/` 商品详情图；外域或其他地址会显示被拦截的域名。修复后已有失败队列任务需手动重试，原历史错误不会自动清除。

Agent 只向模型提供尚未填写的类目枚举规则；模型越界返回的字段、文本输入建议或无事实支持的选项会被忽略，不能进入发布数据。真实必填项仍由平台 schema 在提交前校验。已生成草稿但被队列拦截的任务不会自动重试，可在发布工作台核对草稿后手动重新运行 Agent。

对采集脚本只给正式 SKU 留下合并标签（如「黑色>有线款」）的情况，若来源 `skuProps` 明确给出相同顺序的维度及每个候选值，Agent 会逐项验证后还原「颜色分类」「规格尺寸」等属性，再按平台规格规则生成 SKU 表。维度数量、顺序或候选值不能一一对应时不猜测，仍需人工映射；已有草稿在发布工作台重新运行 Agent 时可使用来源记录补齐映射。

真实模型样例测试：设置 `RUN_LIVE_QWEN=1` 和 `PLAYWRIGHT_MODULE`（可用 Playwright 的 `index.mjs` 路径），运行 `npm run test:qwen-agent-live`。此测试调用百炼并产生模型费用，包含一张已同步商品图及自建水印测试图，不向真实店铺上传或发布。当前真实文本/图像样例联调已通过，真实商品发布验收仍待指定测试商品与类目。

## 图片编辑与电商套图

- **商品图片**：采集商品详情里按顺序展示主图（首图在前，最多 6 张）和详情图，可放大查看；「检测水印/Logo」用 qwen3.8-flash 检查明确的他人公司/店铺水印和知名品牌 Logo，结果按图片缓存。
- **图片编辑**（左侧菜单）：白底图、换背景使用千问 `qwen-image-3.0` / `-pro` / `2.1-pro`，在后台排队生成；改尺寸在本地完成（800×800、750×1000、790×1000 等或自定义，补白或智能裁切）。原图可来自采集商品、上传图片或已生成图片。
- **电商套图**（左侧菜单）：选择采集商品（或填写商品名）和 1–4 张参考图，用 APIMart `gpt-image-2.5-flare`（快）或 `-sunburst`（细节更准）生成白底、场景氛围、细节、模特场景、卖点、规格尺寸 6 张图；卖点和规格只使用商品资料与填写的信息。需在服务器配置 `APIMART_API_KEY`。
- **AI 图片自动处理**（系统设置，默认关闭）：开启后，Agent 检查之后新采集商品的主图；对带明确他人水印或品牌 Logo 的位置，只用其余干净图片作参考生成替代图，原图保持不变，结果在商品详情里人工确认后使用。
- **不提供去水印**：带他人水印或品牌 Logo 的图片不会被编辑或用作参考，提示词中要求去水印/Logo 也会被拒绝——去除别人的水印和商标属于侵权。
- **上传相册并替换主图**：生成图卡片上的「替换主图」把图片上传到所选店铺的 1688 相册（填写相册 ID，按店铺记住），再替换或追加到采集商品的主图；已转正式产品的同步更新产品图片，可随时「撤销」恢复原图。复检未通过的图不能上传；相册上传结果不确定时会标记“待核对”，不会自动重传。商品若在 Agent 队列被拦截，换图后可直接重新提交。需要 `integration:publish` 权限。
- 所有结果以私有对象存入 OSS（`image-workshop/<租户>/`），生成后再次检测，页面用一小时有效的签名链接预览，可下载 PNG。生成会产生百炼 / APIMart 费用。
- 迁移 `039_image_workshop.sql`、`040_image_album_apply.sql`；模拟接口测试 `npm run test:image-workshop`。

## 数据模型约定

- 所有业务金额统一使用人民币 `CNY`，数据库使用定点数存储。
- 线下客户使用省、市、区县及详细地址描述国内区域。
- 产品价格按数量和客户等级匹配，不维护外币或海外区域价格。
- 时间统一存储为 UTC，界面按 `Asia/Shanghai` 展示。
- 已部署结构只通过新的编号迁移演进，不改写历史迁移。

平台商品详情支持“移入回收站”，需要集成管理和发布权限并确认目标店铺、商品及 ID。先应用迁移 `021_1688_listing_deletion.sql`。仅 `isSuccess: true` 标记删除成功，本地产品和关联记录保留；超时或结果不明时停止重复提交，需在 1688 网站核对。网站可手动恢复或永久清除，CRM 不执行永久删除。`npm run test:1688-delete` 使用模拟网关验证，无真实删除。

## 1688 客服绩效

绩效应用是独立的 1688 应用，必须单独授权，不能复用商品令牌。在 `.env.local` 配置 `ALI1688_PERFORMANCE_APP_KEY`、`ALI1688_PERFORMANCE_APP_SECRET`、`ALI1688_PERFORMANCE_REDIRECT_URI`（三项必须同时配置，且 AppKey 不能与商品应用相同），应用迁移 `022_1688_performance_app.sql` 后重启 API。进入「客服绩效 → 绩效应用授权」，用店铺**主账号**授权，粘贴回跳地址完成连接，再点击“验证”确认主账号和子账号数；子账号授权会被提示重新授权。「指标口径」可修改询单归属窗口（默认 72 小时）和未回复判定（默认 180 秒），需要 `performance:manage`；默认绩效方案（默认方案 1：优先给促成下单的客服）仅财务（`payroll:manage`）可修改。模拟网关与真实数据库验证：`npm run test:1688-performance`。

应用迁移 `023_1688_performance_reception.sql`、`024_1688_performance_reply_modes.sql` 后，API 进程会每 15 分钟（`PERF_SYNC_INTERVAL_MS`）自动增量同步主/子账号与旺旺会话消息；首次同步最近 `PERF_SYNC_INITIAL_DAYS`（默认 7）天，「客服账号」中可手动“立即同步”，本次范围可选今天 / 近 7 天 / 近 30 天（只拉该时间段的订单、退款和会话，调用少、完成快）或全部（含历史补齐）；“历史数据范围”可选近 7/30/60/90 天（默认 30 天，迁移 `036_perf_sync_scope.sql`），自动同步只补齐到该范围，范围外已同步的数据保留但不再继续拉取，状态栏显示订单/会话补齐进度、待拉取会话数和今日调用次数。客服消息文本随同步采集（平台不提供买家原文）：保存前遮盖手机号、微信号、QQ 号与长数字，文本保留 90 天；「关键词」页维护店铺的旺旺关键词库（保存在 1688，对所有客服账号生效）：可按分类添加或删除、一键添加常用词（售后退款、投诉差评、物流催单、发票、议价、定制大单）、与平台核对；买家消息正文被平台隐藏，关键词命中是了解买家意图的唯一途径，且只对添加之后的新消息生效。页面统计每个词被买家和客服提到的次数并可打开会话，经营看板提示命中“售后退款/投诉差评”的会话。规则调整后可运行 `npx tsx scripts/reclassify-agent-text.ts`（先加 `--dry-run` 预览）对已保存的遮盖文本重新判定；规则用例 `npm run test:chat-text`。「回复质量」页按客服统计平均回复字数、极短回复、图片/卡片、生硬用语，并列出站外交易风险（发手机号、微信、QQ、站外付款用语、非阿里系链接），经营看板待处理同步提示。为节省调用额度，只拉会话时间有变化的会话（不再每小时重拉当天会话），定时同步对近 7 天没有会话的客服账号每 2 小时查一次，手动同步始终查询全部账号。打开页面只读取本地数据，不会触发同步（应用迁移 `030_perf_sync_history.sql` 后回补可续传：平台限流或中断后，后续定时同步从断点继续；平台会话关系只保留近 90 天；调用频率由 `PERF_SYNC_MAX_QPS` 控制，默认 4 次/秒），并把每个子账号绑定到一个系统用户。只保存消息元数据（方向、时间、类型），不保存聊天正文。「客服对比」「分时接待」按所选店铺和日期统计；只有 `performance:read_own` 的业务员只能看到绑定到自己的账号。客服侧“其他消息”接口不提供内容，默认不计为人工回复，可在「指标口径」切换。应用迁移 `031_perf_work_hours.sql` 后，响应时间按客服工作时段计算（默认 09:00–22:00，北京时间，可在「指标口径」关闭或修改）：时段外进来的咨询从下一次上班开始计时，当天未回复的轮次取次日同会话的首条人工回复。模拟网关验证：`npm run test:1688-performance-sync`。应用迁移 `032_perf_owner_memo_schemes.sql` 后，9 种绩效方案全部可选：方案 5 按订单备注中的“@客服名”或「客服账号」页设置的旗帜对应客服归属；方案 8/9 使用客户的所属客服（「客户经营」资料中可手动指定，未指定时自动归给最早付款订单的方案2 客服）；方案 7/9 分成比例和自动指派在「指标口径」由财务维护。应用迁移 `034_perf_commission_tiers.sql` 后，「工资管理 → 工资规则」可选择按客服比例或阶梯提成（超额累进/全额累进，带试算），并可设置提成最低为 0；工资单明细显示分档计算过程。

应用迁移 `025_1688_performance_orders.sql` 后，同步同时拉取订单与退款（只读，不保存收货地址和联系方式），并按买家下单/付款前在归属窗口内收到的最后一条人工回复，计算 6 种绩效方案下的订单归属。「客服对比」增加询单、售后、新客、转化率和绩效销售额；「聊天分析」按未下单、下单未付款、促成付款、售后分类；「订单归属」显示每个订单归属的客服与依据，可切换方案对比。默认方案由财务在「指标口径」设置（方案 5、8、9 暂不可用）。模拟网关验证：`npm run test:1688-performance-orders`。

应用迁移 `026`–`028` 后：「综合排行」按销售经理设置的指标与权重计算综合能力指数（同期最优者为 100 分）；「我关注的」按账号保存关注指标，可导出 CSV；「工资管理」仅财务（`payroll:manage`）可配置规则并生成月度工资单：工资 = 基本工资 +（当月付款的绩效销售额 − 当月退款）× 提成比例 + KPI 名次奖金 + 奖惩，草稿可重算，锁定后不可修改。验证：`npm run test:1688-performance-payroll`。规划与后续阶段见 [1688 客服绩效与客户经营规划](./docs/1688-performance-crm-plan.md)。

## 客户经营（1688 线上客户）

应用迁移 `029_customer_operations.sql` 后，左侧「客户经营」管理 1688 买家（线上客户）；线下客户仍在「客户」模块，可在客户资料中关联。平台不提供买家姓名和联系方式，名称、电话、旺旺号等需在「资料」中手动维护；购买次数、累计金额、客单价、购买周期、最近/首次交易由同步的订单自动统计（购买周期系统规则：（最后一次 − 首次购买日期）÷（购买次数 − 1））。客户列表支持按购买类型、客户类型、会员身份、分销渠道、客户等级、客单价、标签、回访次数、超期未购和购买周期筛选，可批量打标签；「写跟进」记录跟进方式与下次跟进时间，「待跟进」列出到期客户；「未成交客户」列出下单未付款和咨询未下单的买家；「分层与标签」由销售经理调整分层阈值（立即生效）和标签库。权限：`customer_ops:read/update/manage`。验证：`npm run test:customer-ops`。应用迁移 `033_customer_attachments_overdue.sql` 后：客户资料可上传图片（≤2MB）和文件（≤1MB），各最多 10 个，存私有 OSS（需配置 `OSS_*`），通过 10 分钟签名链接查看；超期未购的客户会自动出现在「待跟进」（可在「分层与标签」关闭）；销售经理可按当前筛选导出客户 CSV（含联系方式，记录审计日志）。
